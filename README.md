# آرکان گلد — پروژه Astro (نسخه‌ی به‌روزشده)

پیاده‌سازی صفحات اصلی سایت آرکان گلد با Astro + Tailwind CSS، راست‌به‌چپ (RTL)، فارسی،
با اتصال زنده به API قیمت طلا و هویت بصری جدید.

> **مستند کامل و خلاصه‌ی پروژه:** [`PROJECT.md`](PROJECT.md): معماری، صفحه‌ها، API ها، سئو، مجله، متغیرهای محیطی، دیپلوی و کارهای رایج.

## اجرای پروژه

```bash
npm install
npm run dev       # اجرای محلی روی http://localhost:4321
npm run build     # خروجی نهایی: پوشه‌ی dist/app (برنامه‌ی Node.js آماده‌ی آپلود)
npm start         # اجرای سرور production (همان خروجی build) روی http://localhost:4321
```

کل سایت روی **Node.js** اجرا می‌شود؛ راه‌اندازی روی هاست: بخش «اجرا روی Node.js» در انتهای همین فایل.

## اتصال قیمت لحظه‌ای طلا (مهم‌ترین بخش فنی)

تمام قیمت‌های نمایش داده‌شده در سایت (هیرو، ماشین‌حساب خرید/فروش، نوار هدر، نمودار،
صفحه قیمت، فروشگاه) از **یک منبع واحد** تغذیه می‌شوند:

```
src/lib/goldPrice.ts       ← سرویس مرکزی: fetch، نرمال‌سازی، polling هر ۳۰ ثانیه
src/lib/priceBinding.ts    ← اتصال خودکار المان‌های data-price-bind به سرویس بالا
```

### منبع قیمت — فقط API آرکان گلد
```
GET https://api.arkan.gold/market/price
{ "pricePerGramToman": "25531000", "pricePerGramRial": "255310000", "change24h": 0.67,
  "fetchedAt": "2026-10-01T11:23:30.045Z", "disableBuy": false, "disableSell": false, ... }
```
`pricePerGramToman` همان قیمت هر گرم طلای ۱۸ عیار است که در کل سایت نمایش داده می‌شود
(ضریب تبدیلی لازم نیست). آدرس پایه با `PUBLIC_ARKAN_API_URL` قابل تغییر است.

### استفاده در یک کامپوننت جدید
هر جای سایت که بخواهید قیمت زنده نشان دهید، کافی است:

```html
<span data-price-bind="pricePerGram" data-price-format="toman">در حال دریافت...</span>
<span data-price-bind="changePercent">--</span>
<span data-price-bind="fetchedAt">--</span>
```

و در یک تگ `<script>` همان فایل:

```js
import '../lib/priceBinding'; // یا مسیر نسبی صحیح بسته به عمق پوشه
```

با این کار المان به‌صورت خودکار در بارگذاری اول و سپس هر ۳۰ ثانیه بروزرسانی می‌شود
(بدون نیاز به نوشتن کد fetch تکراری).

برای منطق سفارشی‌تر (مثل ماشین‌حساب که باید ضرب در گرم انجام دهد)، مستقیماً از
`subscribeGoldPrice()` استفاده کنید — نمونه‌ی کامل در `src/components/sections/Hero.astro`
و `GoldCalculator.astro` موجود است.

### نمودار قیمت (Chart.js)
داده‌ی نمودار از API تاریخچه خوانده می‌شود:
```
GET https://api.arkan.gold/market/price/history?hours=24
[ { "time": "2026-09-30T11:25:00.046Z", "priceRial": "253410000", "priceToman": "25341000" }, ... ]
```
تب‌های «۱ ساعت / ۶ ساعت / ۲۴ ساعت / هفتگی / ماهانه» به ترتیب `hours=1, 6, 24, 168, 720`
را درخواست می‌کنند (آرایه‌ی `ranges` در `src/components/sections/PriceChart.astro`).
تاریخچه‌ی بازه‌ی فعال هر دقیقه دوباره خوانده می‌شود و بین آن، قیمت لحظه‌ای جدید به انتهای
نمودار اضافه می‌شود. کمترین/بیشترین قیمت و درصد تغییر همان بازه زیر نمودار نمایش داده می‌شود.

### فیلدهای دیگر پاسخ API که استفاده می‌شوند
- `disableBuy` / `disableSell` → غیرفعال کردن دکمه‌ی خرید/فروش در هیرو و `GoldCalculator.astro`
- `change24h` → نمایش درصد تغییر (سبز/قرمز) در همه‌جا
- `fetchedAt` → «آخرین بروزرسانی»

## نوار قیمت زنده — نمایش در موبایل

نوار قیمت لحظه‌ای زیر هدر اکنون در **همه‌ی اندازه‌های صفحه از جمله موبایل** نمایش داده
می‌شود (قبلاً فقط در دسکتاپ بود). در منوی تمام‌صفحه‌ی موبایل نیز یک نسخه‌ی کوچک از قیمت
زنده بالای فهرست لینک‌ها تکرار شده تا همیشه در دید کاربر باشد. این بخش‌ها در
`src/components/Header.astro` قرار دارند و مثل همیشه از `src/lib/priceBinding.ts` تغذیه
می‌شوند.


1. **CORS در production** — قیمت، تاریخچه و محصولات مستقیماً از مرورگر از `api.arkan.gold`
   خوانده می‌شوند؛ این سرور باید برای دامنه‌ی `https://arkan.gold` هدر `Access-Control-Allow-Origin` بدهد.
2. **آدرس تصاویر و لینک خرید** — آدرس تصاویر (`primaryImageUrl`, `images[].url`) و `buyUrl` همان‌طور
   که API برمی‌گرداند استفاده می‌شوند؛ در production باید دامنه‌ی واقعی و https باشند (نه `localhost`).
3. **فونت**: فایل `Vazirmatn-Variable.woff2` را در `public/fonts/` قرار دهید
4. **فرم تماس و ورود**: اتصال به backend واقعی

## صفحه‌ی قوانین و مقررات (`/rules`)

متن کامل قوانین (۱۷ بخش) اکنون به‌صورت ساختاریافته در `src/data/rules.ts` نگهداری می‌شود.
صفحه‌ی `src/pages/rules.astro` این داده را می‌خواند و یک فهرست موضوعات چسبان (sticky)
در کنار محتوا نمایش می‌دهد؛ کلیک روی هر آیتم فهرست با اسکرول نرم به همان بخش می‌رود و
هنگام اسکرول صفحه، آیتم فعال فهرست به‌صورت خودکار هایلایت می‌شود (`IntersectionObserver`).

برای ویرایش متن قوانین در آینده، فقط کافی است آرایه‌ی `rulesSections` در
`src/data/rules.ts` را ویرایش کنید؛ افزودن یک بخش جدید به آرایه به‌طور خودکار هم در فهرست
موضوعات و هم در محتوای صفحه ظاهر می‌شود.

## فروشگاه — شمش طلا از API آرکان گلد

فروشگاه فقط یک نوع محصول دارد: **شمش طلا**. همه‌ی اطلاعات از API خوانده می‌شود
(`src/lib/goldIngots.ts`):

```
GET https://api.arkan.gold/public/gold-ingots?page=1&limit=50&inStock=true   ← فهرست (حداکثر ۵۰ در هر صفحه، همه صفحات خوانده می‌شوند)
GET https://api.arkan.gold/public/gold-ingots/{slug}                         ← جزئیات هر شمش
```

- صفحه‌ی `/shop` و صفحه‌ی هر شمش `/shop/{slug}` **هنگام بازدید روی سرور** از API ساخته می‌شوند
  (نام، تصاویر، توضیحات، جدول `specifications` دقیقاً مطابق API، وزن‌ها، بسته‌بندی‌ها، مراحل خرید و
  سوالات متداول). شمشی که در پنل اضافه شود **همان لحظه** صفحه‌ی کامل با سئو دارد و در
  `/sitemap-shop.xml` می‌آید؛ build لازم نیست. شمش حذف‌شده ۴۰۴ واقعی می‌گیرد.
  HTML صفحه از `src/lib/ingotDetail.ts` و رفتار تعاملی آن از `src/lib/ingotDetailClient.ts` می‌آید.
- **کش سرور**: داده‌ی API ۶۰ ثانیه کش می‌شود؛ اگر API قطع شود تا ۱ ساعت آخرین نسخه‌ی سالم نمایش داده
  می‌شود (بعد از آن فهرست در مرورگر بارگذاری و صفحه‌ی محصول ۵۰۳ می‌شود).
- **ترتیب پیش‌فرض فروشگاه:** ارزان‌ترین اول و در قیمت برابر، سبک‌ترین اول (`compareIngots` در `src/lib/ingotCard.ts`).
- **سئو صفحه‌ی محصول:** title/description اختصاصی، `og:type=product` و متاتگ‌های `product:*`،
  JSON-LD شامل `Product` (با `Offer`/`AggregateOffer` به ریال — `IRR`)، `BreadcrumbList`، `FAQPage` و
  `ItemPage`. قیمت schema با هر بازدید از API خوانده می‌شود و با قیمت نمایش‌داده‌شده یکی است.
- **قیمت لحظه‌ای:** در مرورگر هم با هر بروزرسانی قیمت طلا (هر ۳۰ ثانیه) همین API دوباره خوانده می‌شود
  و `finalPriceToman` هر وزن، موجودی و `serviceEnabled` به‌روز می‌شوند (`src/lib/liveIngots.ts`).
  شمشی که بعد از باز شدن صفحه اضافه شود هم به `/shop` اضافه می‌شود.
- **خرید:** کلیک روی کارت محصول همیشه ابتدا صفحه‌ی جزئیات را باز می‌کند. در آنجا کاربر وزن را
  انتخاب می‌کند و دکمه‌ی «خرید شمش» (یا نوار خرید ثابت پایین صفحه در موبایل) او را به `buyUrl` همان وزن
  (`variants[].buyUrl`) در داشبورد آرکان گلد می‌برد. لینک مستقیم به یک وزن: `/shop/{slug}?variant={id}`.
  آدرس قدیمی `/shop/item?slug=...` با ۳۰۱ به `/shop/{slug}` می‌رود.
- اگر `serviceEnabled` برابر `false` باشد، دکمه‌های خرید غیرفعال و پیام «فروش موقتاً غیرفعال است»
  نمایش داده می‌شود.

## استعلام اصالت شمش (`/verify`)

- فرم استعلام با **کد ۸ رقمی عددی** هولوگرام شمش؛ اعداد فارسی خودکار به لاتین تبدیل می‌شوند.
- لینک مستقیم برای QR روی کارت شمش: `https://arkan.gold/verify?code=12345678`
- نتیجه: نام محصول، کد محصول، کد GTIN، ابعاد، وزن، عیار، کشور سازنده، شرکت سازنده، برند،
  نام و نام خانوادگی مالک و تاریخ مالکیت.
- سمت سرور: افزونه‌ی وردپرس `wordpress/arkan-bar-verify/` (نسخه ۲) را در `wp-content/plugins`
  کپی و فعال کنید. منوی «شمش‌های آرکان» برای ثبت دستی (همه‌ی فیلدهای بالا؛ عیار، کشور، سازنده و برند
  مقدار پیش‌فرض دارند) و زیرمنوی «درون‌ریزی CSV» برای ثبت گروهی با ستون‌های
  `code,product,product_code,gtin,dimensions,weight,purity,country,manufacturer,brand,owner_name,owned_at,status`
  — فایل نمونه با کد `12345678`: `wordpress/arkan-bar-verify/sample-bars.csv`.
- کد باید دقیقاً ۸ رقم و یکتا باشد (کد تکراری ذخیره نمی‌شود).
- API: `GET /wp-json/arkan/v1/verify-bar?code=12345678` — محدودیت ۳۰ درخواست در ۱۰ دقیقه برای هر IP.

## مجله آرکان گلد — وردپرس هدلس + SSR (`/mag`)

نویسنده‌ها مثل قبل در **پنل وردپرس** کار می‌کنند (نقش‌های نویسنده/ویرایشگر/مدیر، کتابخانه‌ی رسانه،
دسته و برچسب، زمان‌بندی انتشار، Yoast SEO یا Rank Math). صفحه‌های `https://arkan.gold/mag` هنگام هر
بازدید روی سرور Node.js سایت از REST API وردپرس ساخته می‌شوند (SSR): HTML کامل با همه‌ی تگ‌های سئو،
و **انتشار مطلب به build نیاز ندارد**. وردپرس روی `https://cms.arkan.gold` فقط نقش پنل محتوا را دارد و
نباید در نتایج جست‌وجو بیاید (پایین‌تر). آدرس API پیش‌فرض `https://cms.arkan.gold/wp-json` است؛ با
`PUBLIC_WP_API_URL` قابل تغییر است و `PUBLIC_WP_API_URL=off` مجله را غیرفعال می‌کند.

**تصاویر مطالب** با آدرس سایت اصلی سرو می‌شوند: `https://arkan.gold/wp-content/uploads/...` (`src/mag/media.ts`).
بار اول از وردپرس دانلود و در پوشه‌ی `cache/uploads` برنامه ذخیره می‌شوند و بعد از آن مستقیم از دیسک
(حتی در قطعی وردپرس). آدرس‌های قدیمی `arkan.gold/mag/wp-content/uploads/...` با ۳۰۱ به آدرس جدید می‌روند.

### طراحی صفحه‌های مجله (`src/components/mag/`)
- **صفحه‌ی اصلی مجله** (`MagLanding.astro`):
  - ۵ مطلب ویژه بالای صفحه. مطالبی که در وردپرس «سنجاق» شده‌اند (ویرایش مطلب ← «سنجاق کردن به بالای وبلاگ») اول نمایش داده می‌شوند، بعد جدیدترین‌ها.
  - بخش اختصاصی ۳ دسته‌ی پرمطلب.
  - بنر قیمت لحظه‌ای طلا و بنر خرید طلا.
  - «آخرین مطالب» با تب دسته‌ها و صفحه‌بندی (`/mag/page/2`).
- **صفحه‌ی مطلب** (`MagArticle.astro`):
  - کارت سفید شامل نویسنده، تاریخ، زمان مطالعه و دکمه‌های اشتراک‌گذاری.
  - فهرست مطالب خودکار از عنوان‌های h2 و h3 (از ۳ عنوان به بالا)، با برجسته شدن بخش فعلی هنگام اسکرول.
  - نوار پیشرفت مطالعه، برچسب‌ها و معرفی نویسنده.
  - ستون کناری چسبان: قیمت لحظه‌ای طلا با دکمه‌ی خرید و فروش، آخرین مطالب، دسته‌بندی‌ها و استعلام اصالت.
  - ۴ مطلب مرتبط در پایین صفحه.
- **آرشیوها** (دسته، برچسب، نویسنده و جست‌وجو): سربرگ تیره‌ی برند و شبکه‌ی کارت‌ها.
- **کارت مطلب** (`MagCard.astro`) سه حالت دارد: `card`، `overlay` و `mini`. بخش «مطالب مجله»ی صفحه‌ی اصلی سایت هم از همین کارت استفاده می‌کند.

### Rank Math (Pro) — تنظیمات لازم
سایت از Rank Math این‌ها را می‌خواند (`src/lib/magazine.ts` و افزونه‌ی `arkan-headless` نسخه ۲.۲):
- عنوان سئو، توضیحات متا و robots.
- تصویر شبکه‌های اجتماعی، با آدرس arkan.gold.
- schema های Pro: FAQ، HowTo، ویدیو، دستور پخت، دوره، رویداد، نقد و ... . آدرس‌های داخلشان به arkan.gold تبدیل می‌شوند.
- noindex هر مطلب، دسته، برچسب و نویسنده. این صفحه‌ها از `/mag/sitemap.xml` هم حذف می‌شوند.
- ریدایرکت‌های ماژول Redirections، روی `arkan.gold/mag`: انطباق exact، contains، start، end و regex، و کدهای ۳۰۱، ۳۰۲، ۳۰۷، ۴۱۰ و ۴۵۱.

Article، BlogPosting، Breadcrumb و Organization را خود سایت می‌سازد. نسخه‌ی Rank Math این‌ها کنار گذاشته می‌شود تا تکراری نشوند.

| تنظیم در Rank Math | مقدار | دلیل |
|---|---|---|
| تنظیمات عمومی ← سایر ← **Headless CMS Support** | **روشن** (ضروری) | بدون آن سایت به داده‌های سئوی Rank Math دسترسی ندارد |
| ماژول **Sitemap** | خاموش | sitemap مجله روی arkan.gold ساخته می‌شود؛ sitemap رنک مث آدرس‌های cms را دارد |
| ماژول **Instant Indexing** | خاموش | آدرس‌های cms را به بینگ/IndexNow می‌فرستد |
| ماژول **404 Monitor** | خاموش | صفحه‌های عمومی cms به arkan.gold هدایت می‌شوند و این ماژول چیزی ثبت نمی‌کند |
| ماژول **Redirections** | روشن (اختیاری) | روی arkan.gold/mag اجرا می‌شود؛ تغییرات حداکثر ۵ دقیقه بعد یا بلافاصله بعد از «پاک کردن کش مجله» |
| ماژول **Schema** (Pro) | روشن | FAQ و HowTo و ... در نتایج گوگل |
| ماژول **Analytics** | اختیاری | آمار را مستقیم از Search Console دامنه‌ی arkan.gold ببینید |
| عنوان‌ها و متا ← عمومی ← قالب عنوان | `%title% %sep% %sitename%` | نام سایت (تنظیمات ← عمومی ← عنوان سایت) را «مجله آرکان گلد» بگذارید |
| عنوان‌ها و متا ← تصویر پیش‌فرض OpenGraph | یک تصویر برند | برای مطالب بدون تصویر شاخص |
| تنظیمات عمومی ← پیوندها ← **Strip Category Base** | تغییر ندهید | آدرس دسته‌ها عوض می‌شود و آدرس‌های ایندکس‌شده از دست می‌روند |
| تنظیمات عمومی ← Breadcrumbs | لازم نیست | سایت مسیر صفحه را خودش می‌سازد |

### ویرایش مطلب روی سایت دیده نمی‌شود؟
- **حداکثر تأخیر:** حدود ۲.۵ دقیقه، حتی بدون پاک‌سازی کش. مرورگر صفحه‌های مجله را نگه نمی‌دارد (`max-age=0`).
- **دیده شدن فوری:** در وردپرس ← تنظیمات ← مجله هدلس، «توکن پاک‌سازی کش» باید با متغیر `MAG_REVALIDATE_TOKEN` سرویس روی رانفلر یکی باشد (حداقل ۱۶ کاراکتر). دکمه‌ی «پاک کردن کش مجله» را بزنید. نتیجه‌ی «آخرین درخواست» باید `HTTP 200` باشد:
  - `HTTP 404`: متغیر `MAG_REVALIDATE_TOKEN` روی سرویس تعریف نشده یا کوتاه است (بعد از تعریف، سرویس را ری‌استارت کنید).
  - `HTTP 401`: توکن دو طرف یکی نیست.
  - خطای اتصال: وردپرس به `arkan.gold` دسترسی ندارد.
- **چند instance:** اگر سرویس روی رانفلر بیش از یک instance دارد، پاک‌سازی فقط به یکی می‌رسد. بقیه حداکثر ۲.۵ دقیقه بعد به‌روز می‌شوند.
- **کش روی cms:** افزونه (نسخه ۲.۳) کش پاسخ‌های REST را با هدر no-cache خاموش می‌کند. اگر LiteSpeed Cache یا CDN جلوی cms دارید و باز هم مشکل ماند، در LiteSpeed Cache گزینه‌ی «Cache REST API» را خاموش کنید.

### مخفی ماندن cms.arkan.gold از گوگل
1. افزونه‌ی `wordpress/arkan-headless` (نسخه ۲.۱) فعال باشد: صفحه‌های عمومی cms با ۳۰۱ به همان آدرس در
   `arkan.gold/mag` می‌روند، همه‌ی پاسخ‌های وردپرس هدر `X-Robots-Tag: noindex` دارند و sitemap خود
   وردپرس خاموش است.
2. در **تنظیمات ← خواندن** گزینه‌ی «جلوگیری از ایندکس توسط موتورهای جست‌وجو» را **خاموش** نگه دارید
   (روشن بودنش همه‌ی مطالب را روی arkan.gold هم noindex می‌کند؛ افزونه در این حالت هشدار می‌دهد).
3. برای فایل‌های آپلود که مستقیم از وب‌سرور سرو می‌شوند، این خطوط را **اول** فایل `.htaccess` ریشه‌ی
   `cms.arkan.gold` اضافه کنید:
   ```apache
   <IfModule mod_headers.c>
     Header always set X-Robots-Tag "noindex, nofollow"
   </IfModule>
   ```
4. اگر صفحه‌هایی از cms از قبل در گوگل هستند: در Google Search Console دامنه‌ی `cms.arkan.gold` را اضافه
   و از بخش Removals درخواست حذف موقت بدهید؛ با ۳۰۱ و noindex بالا در چند هفته برای همیشه حذف می‌شوند.
   فایل robots.txt برای cms را روی Disallow نگذارید؛ گوگل باید بتواند ۳۰۱ و noindex را ببیند.

### رفتار سرور مجله (برای اینکه بعداً مشکل‌ساز نشود)
- **کش**: هر صفحه ۲ دقیقه و فهرست دسته‌ها ۱۰ دقیقه کش می‌شود؛ بعد از آن نسخه‌ی قبلی فوراً نمایش
  داده و در پس‌زمینه تازه می‌شود. درخواست‌های هم‌زمان برای یک صفحه فقط یک درخواست به وردپرس می‌فرستند.
- **انتشار فوری**: افزونه‌ی `arkan-headless` بعد از هر انتشار/ویرایش/حذف، کش را پاک می‌کند
  (`POST /mag/wp-revalidate`)؛ بدون آن هم تغییرات حداکثر بعد از ۲ دقیقه دیده می‌شوند.
- **قطعی یا کندی وردپرس**: تا ۲۴ ساعت آخرین نسخه‌ی سالم هر صفحه نمایش داده می‌شود (حداکثر انتظار
  برای وردپرس ۱۰ ثانیه، و بعد از خطا ۳۰ ثانیه درخواست دوباره نمی‌فرستد). صفحه‌ای که هرگز کش نشده
  کد **۵۰۳** با `Retry-After` می‌گیرد که به گوگل می‌گوید مشکل موقت است (نه حذف صفحه).
- **کدهای وضعیت درست**: ۴۰۴ واقعی برای آدرس ناموجود و صفحه‌ی خارج از محدوده (noindex)، ۳۰۱ برای
  آدرس‌های قدیمی وردپرس با `/` در انتها، `/page/1`، `/mag/feed`، sitemapهای Yoast/Rank Math و
  مطلبی که آدرسش عوض شده (مثلا تغییر دسته در ساختار پیوند).
- **حافظه**: حداکثر ۶۰۰ صفحه در کش (چند ده مگابایت در بدترین حالت).

### راه‌اندازی مجله (یک بار)
1. **انتقال وردپرس** به `cms.arkan.gold` (مثلا با Duplicator یا All-in-One WP Migration). در
   «تنظیمات ← عمومی» هر دو نشانی `https://cms.arkan.gold`. «پیوندهای یکتا» را تغییر ندهید. افزونه‌ی
   استعلام شمش همراه وردپرس منتقل می‌شود و API آن خودکار `{PUBLIC_WP_API_URL}/arkan/v1/verify-bar` می‌شود.
2. **build** و آپلود طبق بخش «اجرا روی Node.js» (آدرس وردپرس پیش‌فرض است و تنظیم لازم ندارد). در
   cPanel متغیر `MAG_REVALIDATE_TOKEN` (یک رشته‌ی تصادفی حداقل ۱۶ کاراکتری) را به برنامه اضافه کنید.
   بعد `https://arkan.gold/healthz` را باز کنید: در بخش `magazine` باید `"ok": true` و `home` برابر
   `https://cms.arkan.gold` باشد؛ اگر نه، متن `error` علت را نشان می‌دهد (مثلا بسته بودن REST API).
3. **افزونه‌ی وردپرس** `wordpress/arkan-headless` را نصب و فعال کنید؛ در «تنظیمات ← مجله هدلس» همان
   `MAG_REVALIDATE_TOKEN` را در «توکن پاک‌سازی کش» وارد و «پاک کردن کش مجله» را بزنید (باید موفق باشد).
4. **بررسی**: `https://arkan.gold/mag`، یک مطلب، `https://arkan.gold/mag/sitemap.xml` و یک آدرس اشتباه
   (باید ۴۰۴ بدهد). یک مطلب آزمایشی منتشر کنید و ببینید فوراً روی سایت می‌آید.
5. **Search Console**: sitemap `https://arkan.gold/mag/sitemap.xml` را ثبت کنید.

### آدرس‌ها — حفظ رتبه‌های فعلی
آدرس هر صفحه دقیقاً از فیلد `link` وردپرس گرفته می‌شود؛ هر ساختار «پیوند یکتا» (`/%postname%/`، با
تاریخ، با دسته و ...) همان آدرس زیر `/mag` را دارد: `/mag/{مطلب}`، `/mag/category/{دسته}`،
`/mag/tag/{برچسب}`، `/mag/author/{نویسنده}`، صفحه‌بندی `.../page/2` و جست‌وجو `/mag?s=...`.
لینک‌های داخلی داخل متن مطالب خودکار به `/mag/...` تبدیل می‌شوند. ساختار پیوند «ساده» (`?p=123`)
پشتیبانی نمی‌شود.

### سئو
- **Yoast SEO**: عنوان سئو، توضیحات متا، تصویر شبکه‌های اجتماعی و noindex هر مطلب، دسته، برچسب و نویسنده.
- **Rank Math (و Pro)**: بخش «Rank Math (Pro) — تنظیمات لازم» پایین‌تر.
- بدون افزونه: عنوان مطلب، خلاصه (یا ابتدای متن) و تصویر شاخص.
- canonical، Open Graph و `article:*`، JSON-LD از نوع `BlogPosting` و `BreadcrumbList`، `Blog`/`CollectionPage`
  برای فهرست‌ها، `/mag/sitemap.xml` با `lastmod`، خوراک RSS، و صفحه‌ی جست‌وجو/۴۰۴ با noindex.
- بخش «مطالب مجله» صفحه‌ی اصلی در build ساخته و در مرورگر از وردپرس به‌روز می‌شود.

REST API وردپرس باید عمومی بماند (`/wp-json/wp/v2/` برای posts، pages، categories، tags و users)؛ اگر
افزونه‌ی امنیتی دارید آن را نبندید. بستن `users` فقط آرشیو نویسنده‌ها را غیرفعال می‌کند.

| نوع صفحه | صفحه‌ها | ساخته‌شدن |

- **قیمت طلا در HTML**: در صفحه‌های پویا قیمت لحظه‌ای روی سرور در HTML نوشته می‌شود (نوار قیمت هدر،
  هیرو، ماشین‌حساب، صفحه‌ی قیمت، فروشگاه) — موتورهای جست‌وجو و پیش‌نمایش لینک‌ها قیمت واقعی را
  می‌بینند. (`src/middleware.ts` و `src/lib/serverPrice.ts`؛ قیمت ۲۰ ثانیه کش می‌شود و قیمت قدیمی‌تر از
  ۵ دقیقه هرگز نوشته نمی‌شود.) در مرورگر مثل قبل هر ۳۰ ثانیه به‌روز می‌شود.
- **صفحه‌ی پویای جدید**: در frontmatter صفحه `export const prerender = false;` و اگر قیمت دارد
  `Astro.locals.livePrice = true;` بنویسید.
- **کش سرور** (`src/lib/cache.ts`): مجله ۲ دقیقه (۲۴ ساعت در قطعی وردپرس)، فروشگاه ۶۰ ثانیه (۱ ساعت در
  قطعی API)، قیمت ۲۰ ثانیه (۵ دقیقه در قطعی). درخواست‌های هم‌زمان فقط یک درخواست به API می‌فرستند.
- **سرور** (`server/server.mjs`): فایل‌های ایستا با نسخه‌ی فشرده‌ی br/gzip (در build ساخته می‌شوند)،
  ETag و کش یک‌ساله برای `/_astro`؛ ۳۰۱ برای آدرس‌های با `/` در انتها؛ صفحه‌ی ۴۰۴ سایت؛ هدرهای امنیتی؛
  فایل‌های نقطه‌دار و مسیرهای `..` هرگز سرو نمی‌شوند.
- **وضعیت سرور**: `/healthz` (JSON، با `X-Robots-Tag: noindex`) اتصال به API قیمت، API شمش‌ها و وردپرس
  مجله را نشان می‌دهد — برای مانیتورینگ و عیب‌یابی.
- **sitemap**: `sitemap-index.xml` (همه‌ی صفحه‌های با آدرس ثابت)، `sitemap-shop.xml` (هر شمش، پویا) و
  `mag/sitemap.xml` (مجله، پویا) — همه در `robots.txt`.

### راه‌اندازی روی هاست (cPanel ← Setup Node.js App) — یک بار
1. اگر وردپرس مجله هنوز در `public_html/mag` است، اول آن را به `cms.arkan.gold` منتقل کنید (بخش مجله).
2. از محتوای فعلی `public_html` نسخه‌ی پشتیبان بگیرید و آن را **خالی** کنید (فایل‌های ایستای قبلی؛
   وگرنه LiteSpeed به‌جای برنامه آن‌ها را نمایش می‌دهد).
3. محتوای `dist/app` را در یک پوشه‌ی جدا **بیرون از** `public_html` آپلود کنید، مثلا `/home/USER/arkan-site`
   (با FTP، یا zip با 7-Zip و استخراج در File Manager).
4. **Setup Node.js App ← Create Application**:
   - Node.js version: ۲۰ (حداقل ۱۸)
   - Application mode: Production
   - Application root: `arkan-site`
   - Application URL: `arkan.gold` (بدون مسیر)
   - Application startup file: `app.cjs`
   - Environment variables: `MAG_REVALIDATE_TOKEN` (اگر مجله فعال است)
   - Create، سپس Start. (`Run NPM Install` لازم نیست.)
5. در cPanel ← Domains، گزینه‌ی **Force HTTPS Redirect** را برای `arkan.gold` روشن کنید.
6. **بررسی**: صفحه‌ی اصلی (قیمت باید بدون «در حال دریافت» در سورس صفحه باشد)، `/shop` و یک شمش،
   `/about`، یک آدرس اشتباه (۴۰۴)، `/robots.txt`، `/sitemap-shop.xml` و `/healthz`.
7. **مانیتورینگ** (پیشنهادی): در UptimeRobot یا سرویس مشابه، آدرس `https://arkan.gold/healthz` را هر ۵
   دقیقه چک کنید؛ هم از قطعی باخبر می‌شوید و هم برنامه در هاست اشتراکی به خواب نمی‌رود (بیدار شدن ۱ تا ۳ ثانیه طول می‌کشد).
8. **Search Console**: `sitemap-index.xml`، `sitemap-shop.xml` و `mag/sitemap.xml` را ثبت کنید.

### اجرا روی رانفلر یا هر سرویس Node.js / Docker (بدون cPanel)
پروژه هر دو روش رایج پلتفرم‌های ابری را پشتیبانی می‌کند:

- **سرویس Node.js:** پلتفرم این دستورها را به ترتیب اجرا می‌کند:
  ```bash
  npm ci
  npm run build
  npm start
  ```
  `npm start` سرور production را روی پورت `PORT` اجرا می‌کند (پیش‌فرض ۴۳۲۱). اگر پلتفرم پورت ثابتی می‌خواهد، همان را در متغیر `PORT` بگذارید. نسخه‌ی Node: ۲۰ (حداقل ۱۸.۱۷).
- **Docker:** `Dockerfile` ریشه‌ی پروژه یک ایمیج کوچک می‌سازد (فقط `dist/app`، بدون `node_modules`، کاربر غیر root، پورت ۳۰۰۰، health check روی `/healthz`).
  - متغیرهای `PUBLIC_*` را به‌عنوان build argument بدهید.
  - `MAG_REVALIDATE_TOKEN` را در تنظیمات سرویس، یعنی زمان اجرا، تعریف کنید.
- **حجم آپلود:** `node_modules`، `dist`، `.git` و `dist.zip` را آپلود نکنید. `.dockerignore` همین‌ها را کنار می‌گذارد. اگر پلتفرم فایل ignore جداگانه‌ای برای آپلود دارد، همین فهرست را در آن هم بنویسید.
- **کش تصاویر مجله:** در پوشه‌ی `cache/` ذخیره می‌شود. اگر پلتفرم دیسک ماندگار دارد، آن را روی `/app/cache` (Docker) یا پوشه‌ی `cache` برنامه وصل کنید. بدون دیسک ماندگار هم کار می‌کند و فقط بعد از هر دیپلوی تصاویر دوباره از وردپرس خوانده می‌شوند.
- **دامنه:** `arkan.gold` را به همین سرویس وصل کنید. در `/healthz` وضعیت اتصال به API ها دیده می‌شود.

### دیپلوی خودکار (GitHub Actions)
با هر push یا merge به `main`، فایل `.github/workflows/deploy.yml` سایت را build می‌کند، `dist/app` را روی هاست
آپلود می‌کند و برنامه را از نو راه‌اندازی می‌کند. انتشار مطلب، شمش جدید و تغییر قیمت به دیپلوی نیاز ندارند.
اجرای دستی: تب Actions ← Deploy ← Run workflow.

تنظیمات در GitHub: مخزن ← Settings ← Secrets and variables ← Actions. یکی از دو روش زیر کافی است:

**روش ۱: SSH (پیشنهادی؛ سریع‌تر و مطمئن‌تر)**
1. در cPanel ← **SSH Access** ← Manage SSH Keys ← Generate a New Key (بدون رمز یا با رمز خالی) ← بعد روی
   کلید ساخته‌شده **Manage ← Authorize** بزنید. اگر بخش SSH Access در cPanel نیست، از پشتیبانی هاست بخواهید SSH را فعال کنند.
2. در همان صفحه، کلید خصوصی (Private Key) را View/Download کنید.
3. در GitHub این **Secrets** را بسازید:
   - `SSH_HOST`: آدرس سرور، مثلا `arkan.gold` یا IP سرور
   - `SSH_USERNAME`: نام کاربری cPanel
   - `SSH_PRIVATE_KEY`: متن کامل کلید خصوصی، از خط `-----BEGIN` تا `-----END`
4. اگر پورت SSH هاست ۲۲ نیست، **Variable** با نام `SSH_PORT` بسازید.

**روش ۲: FTP**
- **Secrets:** `FTP_SERVER` (مثلا `ftp.arkan.gold`)، `FTP_USERNAME` و `FTP_PASSWORD`.
- حساب FTP باید به پوشه‌ی خانه دسترسی داشته باشد، نه فقط `public_html`. حساب اصلی cPanel این دسترسی را دارد.
- اگر خطای گواهی (certificate) دیدید، **Variable** با نام `FTP_VERIFY_CERT` و مقدار `false` بسازید.

**Variables مشترک (اختیاری):**
- `APP_DIR`: پوشه‌ی برنامه نسبت به پوشه‌ی خانه (پیش‌فرض `arkan-site`)، همان Application root در cPanel.
- `PUBLIC_GA4_ID`، `PUBLIC_YEKTANET_ID`، `PUBLIC_ENAMAD_ID` و `PUBLIC_ENAMAD_CODE`.

**خطاهای رایج** (متن خطا در تب Actions، روی اجرای قرمز کلیک کنید):

| خطا | علت و راه‌حل |
|---|---|
| «اتصال به هاست برقرار نشد» | هاست اتصال از خارج ایران (سرورهای GitHub) را بسته است. از پشتیبانی هاست بخواهید پورت SSH (یا ۲۱ برای FTP) را برای IPهای خارجی باز کنند. |
| «ورود SSH ناموفق» | کلید در cPanel Authorize نشده یا `SSH_PRIVATE_KEY` ناقص کپی شده است. |
| «آپلود FTP ناموفق» | نام کاربری یا رمز، یا مقدار `APP_DIR` را بررسی کنید. |
| «هیچ روش آپلودی تنظیم نشده» | Secrets بالا را بسازید. تا آن موقع push به `main` فقط هشدار می‌دهد و آپلودی انجام نمی‌شود. |

موقع آپلود فایل‌های قدیمی پاک نمی‌شوند (برنامه‌ی در حال اجرا تا لحظه‌ی راه‌اندازی دوباره سالم می‌ماند) و کش
تصاویر (`cache/`) هم دست نمی‌خورد. آپلود دستی هم همین‌طور است: محتوای `dist/app` را روی همان پوشه بریزید و
`tmp/restart.txt` را آخر از همه آپلود کنید، یا در cPanel دکمه‌ی Restart را بزنید.

لاگ خطاها: cPanel ← Setup Node.js App یا فایل `stderr.log` در پوشه‌ی برنامه.
