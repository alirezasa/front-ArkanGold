# آرکان گلد — پروژه Astro (نسخه‌ی به‌روزشده)

پیاده‌سازی صفحات اصلی سایت آرکان گلد با Astro + Tailwind CSS، راست‌به‌چپ (RTL)، فارسی،
با اتصال زنده به API قیمت طلا و هویت بصری جدید.

## اجرای پروژه

```bash
npm install
npm run dev       # اجرای محلی روی http://localhost:4321
npm run build     # خروجی نهایی برای دیپلوی، در پوشه dist
npm run preview   # پیش‌نمایش خروجی build شده
```

## هویت بصری جدید

| نقش | کد رنگ | توکن Tailwind |
|---|---|---|
| رنگ اصلی (زرشکی تیره) | `#330509` | `brand` (و `maroon` به‌عنوان alias قدیمی) |

فونت‌ها یک پله درشت‌تر از قبل تنظیم شده‌اند (`tailwind.config.mjs` → `theme.extend.fontSize`).

## اتصال قیمت لحظه‌ای طلا (مهم‌ترین بخش فنی)

تمام قیمت‌های نمایش داده‌شده در سایت (هیرو، ماشین‌حساب خرید/فروش، نوار هدر، نمودار،
صفحه قیمت، فروشگاه) از **یک منبع واحد** تغذیه می‌شوند:

```
src/lib/goldPrice.ts       ← سرویس مرکزی: fetch، نرمال‌سازی، polling هر ۳۰ ثانیه
src/lib/priceBinding.ts    ← اتصال خودکار المان‌های data-price-bind به سرویس بالا
```

### منبع قیمت — فقط API آرکان گلد
```
GET https://api.arkan.gold/market/price
{ "pricePerGramToman": "25531000", "pricePerGramRial": "255310000", "change24h": 0.67,
  "fetchedAt": "2026-10-01T11:23:30.045Z", "disableBuy": false, "disableSell": false, ... }
```
`pricePerGramToman` همان قیمت هر گرم طلای ۱۸ عیار است که در کل سایت نمایش داده می‌شود
(ضریب تبدیلی لازم نیست). آدرس پایه با `PUBLIC_ARKAN_API_URL` قابل تغییر است.

### استفاده در یک کامپوننت جدید
هر جای سایت که بخواهید قیمت زنده نشان دهید، کافی است:

```html
<span data-price-bind="pricePerGram" data-price-format="toman">در حال دریافت...</span>
<span data-price-bind="changePercent">--</span>
<span data-price-bind="fetchedAt">--</span>
```

و در یک تگ `<script>` همان فایل:

```js
import '../lib/priceBinding'; // یا مسیر نسبی صحیح بسته به عمق پوشه
```

با این کار المان به‌صورت خودکار در بارگذاری اول و سپس هر ۳۰ ثانیه بروزرسانی می‌شود
(بدون نیاز به نوشتن کد fetch تکراری).

برای منطق سفارشی‌تر (مثل ماشین‌حساب که باید ضرب در گرم انجام دهد)، مستقیماً از
`subscribeGoldPrice()` استفاده کنید — نمونه‌ی کامل در `src/components/sections/Hero.astro`
و `GoldCalculator.astro` موجود است.

### نمودار قیمت (Chart.js)
داده‌ی نمودار از API تاریخچه خوانده می‌شود:
```
GET https://api.arkan.gold/market/price/history?hours=24
[ { "time": "2026-09-30T11:25:00.046Z", "priceRial": "253410000", "priceToman": "25341000" }, ... ]
```
تب‌های «۱ ساعت / ۶ ساعت / ۲۴ ساعت / هفتگی / ماهانه» به ترتیب `hours=1, 6, 24, 168, 720`
را درخواست می‌کنند (آرایه‌ی `ranges` در `src/components/sections/PriceChart.astro`).
تاریخچه‌ی بازه‌ی فعال هر دقیقه دوباره خوانده می‌شود و بین آن، قیمت لحظه‌ای جدید به انتهای
نمودار اضافه می‌شود. کمترین/بیشترین قیمت و درصد تغییر همان بازه زیر نمودار نمایش داده می‌شود.

### فیلدهای دیگر پاسخ API که استفاده می‌شوند
- `disableBuy` / `disableSell` → غیرفعال کردن دکمه‌ی خرید/فروش در هیرو و `GoldCalculator.astro`
- `change24h` → نمایش درصد تغییر (سبز/قرمز) در همه‌جا
- `fetchedAt` → «آخرین بروزرسانی»

## هدر و فوتر

- **منوها**: همه‌ی آیتم‌ها (هدر دسکتاپ، منوی موبایل و فوتر) از `src/data/nav.ts` خوانده می‌شوند:
  خدمات (خرید و فروش طلای آب‌شده، خرید و فروش شمش طلا، تحویل فیزیکی)، قیمت طلا، محصولات،
  استعلام اصالت شمش، مجوزها و «سایر» (مجله، سوالات متداول، قوانین، درباره ما، تماس با ما).
- **هدر**: کانتینر عریض (تا ۱۷۶۰ پیکسل)، لوگوی `arkan-gold-logo-header.webp`، آیکون پشتیبانی آنلاین
  (در همه‌ی اندازه‌ها بعد از لوگو و قبل از «ورود / ثبت نام»)، نوار قیمت زنده، منوی تمام‌صفحه در
  موبایل و کشوی کناری در تبلت (با آیتم «پشتیبانی آنلاین»)، پاپ‌آپ QR دانلود اپلیکیشن.
- **پشتیبانی آنلاین**: چت آنلاین آرکان گلد (`LIVECHAT_EMBED_URL` = `https://app.arkan.gold/livechat-embed.js`،
  مستندات در مخزن `arkangold` ← `docs/livechat/README.md`) روی همه‌ی صفحات بارگذاری می‌شود. دکمه‌ی
  شناور آن مخفی است (`iframe[data-arkan-chat]` فقط در حالت باز دیده می‌شود) و چت با `ArkanChat.open()`
  از آیکون پشتیبانی و دکمه‌هایی که ویژگی `data-support-chat` دارند باز می‌شود (`src/lib/support.ts`).
  `?chat=open` و شروع گفتگو توسط کارشناس هم پنجره را باز می‌کنند. اگر چت در دسترس نباشد، کاربر به
  `/contact` هدایت می‌شود. اگر روی سایت CSP دارید، `https://app.arkan.gold` را به `script-src` و `frame-src` اضافه کنید.
- **PWA**: `public/manifest.webmanifest` (نام، آیکون‌ها، رنگ برند، حالت standalone) برای نصب سایت روی موبایل.
- **فوتر**: تک‌رنگ `#330509`، ستون برند وسط‌چین (لوگوی لاتین، شعار با فونت بولد سایت، شبکه‌های
  اجتماعی اینستاگرام/بله/واتس‌اپ)، ستون‌های «خدمات و محصولات»، «سایر» و اطلاعات تماس.

## پالت رنگی — تک‌رنگ برند

طبق آخرین تصمیم، پالت رنگی سایت به یک رنگ اصلی محدود شده:

- **`#330509` (برند):** تمام پس‌زمینه‌های تیره (هدر، فوتر، پنل‌ها، دکمه‌ها)، متن‌های کلیدی،
  بوردرها و گرادیان‌های تزئینی — همه از همین یک تن رنگی (با روشن/تیره‌ی جزئی برای عمق بصری)
  ساخته می‌شوند.
- **`#c5a059` (طلایی):** فقط برای جزئیات بسیار کوچک باقی مانده — مثل خط جداکننده‌ی نازک
  (`gold-divider`)، یک نقطه‌ی تزئینی کوچک، یا هاور یک لینک متنی. هیچ‌جا به‌عنوان
  پس‌زمینه‌ی سطح بزرگ، گرادیان اصلی دکمه یا کارت استفاده نمی‌شود.
- روی پس‌زمینه‌های تیره، تمام متن‌ها سفید/روشن هستند (نه طلایی) تا خوانایی حداکثر باشد.

اگر در آینده خواستید این قانون را تغییر دهید، محل تمرکز اصلی `tailwind.config.mjs`
(بخش‌های `backgroundImage` و `colors.brand`) و `src/styles/global.css` (کلاس‌های `.btn-primary`،
`.btn-light`) است.

## نوار قیمت زنده — نمایش در موبایل

نوار قیمت لحظه‌ای زیر هدر اکنون در **همه‌ی اندازه‌های صفحه از جمله موبایل** نمایش داده
می‌شود (قبلاً فقط در دسکتاپ بود). در منوی تمام‌صفحه‌ی موبایل نیز یک نسخه‌ی کوچک از قیمت
زنده بالای فهرست لینک‌ها تکرار شده تا همیشه در دید کاربر باشد. این بخش‌ها در
`src/components/Header.astro` قرار دارند و مثل همیشه از `src/lib/priceBinding.ts` تغذیه
می‌شوند.


1. **CORS در production** — قیمت، تاریخچه و محصولات مستقیماً از مرورگر از `api.arkan.gold`
   خوانده می‌شوند؛ این سرور باید برای دامنه‌ی `https://arkan.gold` هدر `Access-Control-Allow-Origin` بدهد.
2. **آدرس تصاویر و لینک خرید** — آدرس تصاویر (`primaryImageUrl`, `images[].url`) و `buyUrl` همان‌طور
   که API برمی‌گرداند استفاده می‌شوند؛ در production باید دامنه‌ی واقعی و https باشند (نه `localhost`).
3. **فونت**: فایل `Vazirmatn-Variable.woff2` را در `public/fonts/` قرار دهید
4. **فرم تماس و ورود**: اتصال به backend واقعی

## صفحه‌ی قوانین و مقررات (`/rules`)

متن کامل قوانین (۱۷ بخش) اکنون به‌صورت ساختاریافته در `src/data/rules.ts` نگهداری می‌شود.
صفحه‌ی `src/pages/rules.astro` این داده را می‌خواند و یک فهرست موضوعات چسبان (sticky)
در کنار محتوا نمایش می‌دهد؛ کلیک روی هر آیتم فهرست با اسکرول نرم به همان بخش می‌رود و
هنگام اسکرول صفحه، آیتم فعال فهرست به‌صورت خودکار هایلایت می‌شود (`IntersectionObserver`).

برای ویرایش متن قوانین در آینده، فقط کافی است آرایه‌ی `rulesSections` در
`src/data/rules.ts` را ویرایش کنید؛ افزودن یک بخش جدید به آرایه به‌طور خودکار هم در فهرست
موضوعات و هم در محتوای صفحه ظاهر می‌شود.

## فروشگاه — شمش طلا از API آرکان گلد

فروشگاه فقط یک نوع محصول دارد: **شمش طلا**. همه‌ی اطلاعات از API خوانده می‌شود
(`src/lib/goldIngots.ts`):

```
GET https://api.arkan.gold/public/gold-ingots?page=1&limit=50&inStock=true   ← فهرست (حداکثر ۵۰ در هر صفحه، همه صفحات خوانده می‌شوند)
GET https://api.arkan.gold/public/gold-ingots/{slug}                         ← جزئیات هر شمش
```

- در زمان build صفحه‌ی `/shop` و برای هر شمش صفحه‌ی `/shop/{slug}` ساخته می‌شود (نام، تصاویر،
  توضیحات، جدول `specifications` دقیقاً مطابق API، وزن‌ها، بسته‌بندی‌ها، مراحل خرید و سوالات متداول).
  HTML صفحه از `src/lib/ingotDetail.ts` و رفتار تعاملی آن از `src/lib/ingotDetailClient.ts` می‌آید.
- **ترتیب پیش‌فرض فروشگاه:** ارزان‌ترین اول و در قیمت برابر، سبک‌ترین اول (`compareIngots` در `src/lib/ingotCard.ts`).
- **سئو صفحه‌ی محصول:** title/description اختصاصی، `og:type=product` و متاتگ‌های `product:*`،
  JSON-LD شامل `Product` (با `Offer`/`AggregateOffer` به ریال — `IRR`)، `BreadcrumbList`، `FAQPage` و `ItemPage`.
- **قیمت لحظه‌ای:** در مرورگر بلافاصله و سپس با هر بروزرسانی قیمت طلا (هر ۳۰ ثانیه) همین API دوباره
  خوانده می‌شود و `finalPriceToman` هر وزن، موجودی و `serviceEnabled` به‌روز می‌شوند
  (`src/lib/liveIngots.ts`). شمش جدیدی که بعد از آخرین build اضافه شود هم در `/shop` نمایش داده
  می‌شود و کارتش به `/shop/item?slug=...` می‌رود که جزئیات را در مرورگر از API می‌سازد (noindex) تا
  build بعدی صفحه‌ی ایستای آن را بسازد. لینک `/shop/{slug}` چنین شمشی هم از صفحه‌ی ۴۰۴ به همان‌جا هدایت می‌شود.
- **خرید:** کلیک روی کارت محصول همیشه ابتدا صفحه‌ی جزئیات را باز می‌کند. در آنجا کاربر وزن را
  انتخاب می‌کند و دکمه‌ی «خرید شمش» (یا نوار خرید ثابت پایین صفحه در موبایل) او را به `buyUrl` همان وزن
  (`variants[].buyUrl`) در داشبورد آرکان گلد می‌برد. لینک مستقیم به یک وزن: `/shop/{slug}?variant={id}`.
- اگر `serviceEnabled` برابر `false` باشد، دکمه‌های خرید غیرفعال و پیام «فروش موقتاً غیرفعال است»
  نمایش داده می‌شود.
- اگر API هنگام build در دسترس نباشد، build شکست نمی‌خورد و `/shop` محصولات را در مرورگر بارگذاری می‌کند.

### انتشار روی هاست (LiteSpeed / Apache) و آدرس‌های فارسی محصولات

- فایل `public/.htaccess` در build به ریشه‌ی `dist` کپی می‌شود و باید همراه بقیه‌ی فایل‌ها آپلود شود
  (فایل‌های نقطه‌دار در File Manager هاست به‌طور پیش‌فرض مخفی‌اند). اگر روی هاست از قبل `.htaccess`
  دارید، محتوای این فایل را به آن اضافه کنید.
- این فایل صفحه‌ی ۴۰۴ سایت را فعال می‌کند و اگر برای `/shop/{slug}` صفحه‌ی ایستا روی سرور نباشد،
  همان آدرس را با صفحه‌ی جزئیاتی که در مرورگر از API ساخته می‌شود نمایش می‌دهد؛ پس لینک محصول هرگز ۴۰۴ نمی‌شود.
- slug محصولات فارسی است، پس نام پوشه‌ها در `dist/shop/` فارسی است. هنگام zip کردن برای آپلود از
  ابزاری استفاده کنید که نام فایل‌ها را UTF-8 ذخیره کند (مثلاً 7-Zip)؛ zip داخلی ویندوز ممکن است نام
  پوشه‌های فارسی را هنگام استخراج روی هاست خراب کند.
- بعد از اضافه شدن شمش جدید در پنل، یک build و آپلود دوباره انجام دهید تا صفحه‌ی ایستای آن (برای سئو) ساخته شود.

## استعلام اصالت شمش (`/verify`)

- فرم استعلام با **کد ۸ رقمی عددی** هولوگرام شمش؛ اعداد فارسی خودکار به لاتین تبدیل می‌شوند.
- لینک مستقیم برای QR روی کارت شمش: `https://arkan.gold/verify?code=12345678`
- نتیجه: نام محصول، کد محصول، کد GTIN، ابعاد، وزن، عیار، کشور سازنده، شرکت سازنده، برند،
  نام و نام خانوادگی مالک و تاریخ مالکیت.
- سمت سرور: افزونه‌ی وردپرس `wordpress/arkan-bar-verify/` (نسخه ۲) را در `wp-content/plugins`
  کپی و فعال کنید. منوی «شمش‌های آرکان» برای ثبت دستی (همه‌ی فیلدهای بالا؛ عیار، کشور، سازنده و برند
  مقدار پیش‌فرض دارند) و زیرمنوی «درون‌ریزی CSV» برای ثبت گروهی با ستون‌های
  `code,product,product_code,gtin,dimensions,weight,purity,country,manufacturer,brand,owner_name,owned_at,status`
  — فایل نمونه با کد `12345678`: `wordpress/arkan-bar-verify/sample-bars.csv`.
- کد باید دقیقاً ۸ رقم و یکتا باشد (کد تکراری ذخیره نمی‌شود).
- API: `GET /wp-json/arkan/v1/verify-bar?code=12345678` — محدودیت ۳۰ درخواست در ۱۰ دقیقه برای هر IP.

## مجله آرکان گلد — وردپرس هدلس (`/mag`)

نویسنده‌ها مثل قبل در **پنل وردپرس** کار می‌کنند (نقش‌های نویسنده/ویرایشگر/مدیر، کتابخانه‌ی رسانه،
دسته و برچسب، زمان‌بندی انتشار، Yoast SEO یا Rank Math) و این پروژه مطالب را از REST API وردپرس
می‌خواند و با ظاهر سایت اصلی زیر `https://arkan.gold/mag` می‌سازد. وردپرس روی یک ساب‌دامین
(مثلا `cms.arkan.gold`) فقط نقش پنل محتوا را دارد.

### فعال‌سازی
```bash
PUBLIC_WP_API_URL=https://cms.arkan.gold/wp-json npm run build
```
تا وقتی `PUBLIC_WP_API_URL` خالی باشد هیچ صفحه‌ای زیر `/mag` ساخته نمی‌شود و همه‌چیز مثل قبل است
(منوها به وردپرس فعلی لینک می‌دهند). برای دیدن مجله روی سیستم خودتان **همین الان و پیش از انتقال**،
می‌توانید از وردپرس فعلی بخوانید: `PUBLIC_WP_API_URL=https://arkan.gold/mag/wp-json npm run dev`
(فقط برای پیش‌نمایش؛ این خروجی را روی هاست فعلی آپلود نکنید چون با پوشه‌ی وردپرس تداخل دارد).

اگر وردپرس هنگام build در دسترس نباشد، **build عمداً شکست می‌خورد** تا نسخه‌ای بدون مطالب
مجله منتشر نشود.

### فایل‌ها
| فایل | کاربرد |
|---|---|
| `src/lib/wp.ts` | تبدیل پاسخ REST وردپرس، HTML کارت و صفحه‌ی مطلب، سئو و schema (مشترک build و مرورگر) |
| `src/lib/magazine.ts` | خواندن همه‌ی مطالب، برگه‌ها، دسته‌ها، برچسب‌ها و نویسنده‌ها در build و ساخت جدول مسیرها |
| `src/pages/mag/[...path].astro` | همه‌ی صفحه‌های `/mag`: فهرست، صفحه‌بندی، آرشیوها، مطالب و برگه‌ها |
| `src/pages/mag/[feed].xml.ts` / `[sitemap].xml.ts` | `/mag/rss.xml` و `/mag/sitemap.xml` |
| `src/pages/mag-live.astro` | جست‌وجو و نمایش مطلبی که بعد از آخرین build منتشر شده (در مرورگر، noindex) |
| `src/pages/robots.txt.ts` | robots.txt (جایگزین `public/robots.txt`) |
| `wordpress/arkan-headless/` | افزونه‌ی وردپرس: هدایت صفحه‌های وردپرس به سایت اصلی + Deploy Hook |

### آدرس‌ها — حفظ رتبه‌های فعلی
آدرس هر صفحه دقیقاً از فیلد `link` وردپرس ساخته می‌شود؛ هر ساختار «پیوند یکتا» که در وردپرس
تنظیم شده باشد (`/%postname%/`، با تاریخ، با دسته و ...) همان آدرس زیر `/mag` ساخته می‌شود:
`/mag/{مطلب}`، `/mag/category/{دسته}`، `/mag/tag/{برچسب}`، `/mag/author/{نویسنده}` و صفحه‌بندی
`.../page/2`. لینک‌های داخلی داخل متن مطالب (به آدرس وردپرس یا به `arkan.gold/mag`) خودکار به
`/mag/...` تبدیل می‌شوند. `public/.htaccess` آدرس‌های قدیمی `/mag/feed` و sitemap افزونه‌ی سئو
(`/mag/sitemap_index.xml`، `post-sitemap.xml` و ...) را با ۳۰۱ به نسخه‌های جدید می‌برد.
ساختار پیوند «ساده» (`?p=123`) پشتیبانی نمی‌شود.

### سئو
- **Yoast SEO**: عنوان سئو، توضیحات متا، تصویر شبکه‌های اجتماعی و noindex هر مطلب، دسته، برچسب و
  نویسنده از `yoast_head_json` خوانده می‌شود.
- **Rank Math**: در تنظیمات Rank Math گزینه‌ی «Headless CMS Support» را روشن کنید؛ همان داده‌ها از
  `rankmath/v1/getHead` خوانده می‌شوند.
- بدون افزونه: عنوان مطلب، خلاصه (یا ابتدای متن) و تصویر شاخص.
- canonical، Open Graph و `article:*`، JSON-LD از نوع `BlogPosting` (نویسنده، ناشر، تاریخ انتشار و
  ویرایش، دسته، برچسب‌ها)، `BreadcrumbList`، `Blog`/`CollectionPage` برای فهرست‌ها.
- `/mag/sitemap.xml` با `lastmod` هر مطلب (صفحه‌های noindex حذف می‌شوند) و معرفی در `robots.txt`؛
  خوراک RSS با `<link rel="alternate">` در همه‌ی صفحه‌های مجله.

### راه‌اندازی وردپرس (یک بار)
1. وردپرس را به ساب‌دامین `cms.arkan.gold` منتقل کنید (مثلا با افزونه‌ی Duplicator یا All-in-One WP
   Migration) و در «تنظیمات ← عمومی» هر دو نشانی را `https://cms.arkan.gold` بگذارید.
   «تنظیمات ← پیوندهای یکتا» را **تغییر ندهید** تا آدرس مطالب ثابت بماند.
2. افزونه‌ی استعلام شمش (`wordpress/arkan-bar-verify`) همراه وردپرس منتقل می‌شود؛ آدرس API آن
   خودکار `{PUBLIC_WP_API_URL}/arkan/v1/verify-bar` می‌شود.
3. افزونه‌ی `wordpress/arkan-headless` را نصب و فعال کنید. بازدید از صفحه‌های عمومی
   `cms.arkan.gold` با ۳۰۱ به همان آدرس در `arkan.gold/mag` هدایت می‌شود (پیشخوان، REST API،
   پیش‌نمایش پیش‌نویس‌ها و فایل‌های `wp-content/uploads` دست‌نخورده می‌مانند).
4. پروژه را با `PUBLIC_WP_API_URL=https://cms.arkan.gold/wp-json` build و آپلود کنید (پوشه‌ی قدیمی
   `mag` وردپرس دیگر نباید روی هاست اصلی باشد).
5. در Google Search Console، sitemap جدید `https://arkan.gold/mag/sitemap.xml` را ثبت کنید.

### انتشار مطلب جدید
سایت ایستا است؛ برای اینکه مطلب جدید صفحه‌ی ایستا و سئوی کامل داشته باشد، یک build دوباره لازم است:
- **خودکار**: در «تنظیمات ← مجله هدلس» آدرس Deploy Hook را وارد کنید. با هر انتشار، ویرایش، حذف یا
  انتشار زمان‌بندی‌شده (و تغییر دسته/برچسب) یک درخواست POST فرستاده می‌شود؛ تغییرات پشت‌سرهم در ۶۰
  ثانیه یکی می‌شوند. دکمه‌ی «اجرای build الان» هم در همان صفحه هست.
- **تا پیش از build بعدی** لینک مطلب جدید هم کار می‌کند: `.htaccess` آدرس‌هایی از `/mag` را که صفحه‌ی
  ایستا ندارند به `mag-live` می‌دهد که مطلب را در مرورگر از REST API وردپرس نمایش می‌دهد.
- جست‌وجوی مجله (`/mag-live?s=...`) هم مستقیم از وردپرس خوانده می‌شود و همیشه به‌روز است.

### انتشار خودکار (GitHub Actions + FTP)
فایل `.github/workflows/deploy.yml` سایت را build می‌کند و فقط فایل‌های تغییرکرده را با FTP روی هاست
آپلود می‌کند. با هر انتشار مطلب (Deploy Hook افزونه) یا دستی از تب Actions اجرا می‌شود.

1. **این شاخه را در `main` ادغام کنید** — رویداد `repository_dispatch` فقط فایل workflow روی شاخه‌ی اصلی را اجرا می‌کند.
2. **حساب FTP**: در cPanel/DirectAdmin هاست یک حساب FTP بسازید که به پوشه‌ی سایت (`public_html`) دسترسی دارد.
3. **Secrets** (GitHub ← Settings ← Secrets and variables ← Actions ← Secrets):
   `FTP_SERVER` (مثلا `ftp.arkan.gold`)، `FTP_USERNAME`، `FTP_PASSWORD`.
4. **Variables** (همان صفحه ← تب Variables): `PUBLIC_WP_API_URL` = `https://cms.arkan.gold/wp-json`؛
   اختیاری: `FTP_SERVER_DIR` (پیش‌فرض `public_html/`، حتما با `/` در انتها؛ اگر حساب FTP مستقیم در
   `public_html` باز می‌شود `./` بگذارید)، `FTP_PROTOCOL` (پیش‌فرض `ftps`؛ اگر هاست FTPS ندارد `ftp`)،
   و `PUBLIC_GA4_ID`، `PUBLIC_YEKTANET_ID`، `PUBLIC_ENAMAD_ID`، `PUBLIC_ENAMAD_CODE` اگر استفاده می‌کنید.
5. **اجرای اول دستی**: Actions ← Deploy ← Run workflow. اولین اجرا همه‌ی فایل‌ها را آپلود می‌کند.
6. **توکن GitHub برای وردپرس**: GitHub ← Settings (حساب کاربری) ← Developer settings ← Fine-grained tokens
   ← Generate new token؛ Repository access: فقط `alirezasa/front-ArkanGold`؛ Permissions ← Contents: **Read and write**.
7. **وردپرس ← تنظیمات ← مجله هدلس**:
   - آدرس Deploy Hook: `https://api.github.com/repos/alirezasa/front-ArkanGold/dispatches`
   - هدر Authorization: `Bearer github_pat_...` (توکن مرحله‌ی ۶)
   - بدنه‌ی JSON: `{"event_type":"wordpress-publish"}`
   - «اجرای build الان» را بزنید؛ نتیجه‌ی موفق `HTTP 204` است و یک اجرای جدید در تب Actions دیده می‌شود.

اگر هاست ایرانی اتصال از سرورهای خارج از ایران را می‌بندد، FTP یا REST API وردپرس از GitHub در دسترس
نخواهد بود (خطای اتصال در لاگ Actions)؛ در این صورت از پشتیبانی هاست بخواهید دسترسی FTP و
`cms.arkan.gold` را برای IPهای خارجی باز کنند. توکن GitHub تاریخ انقضا دارد؛ قبل از انقضا توکن جدید
بسازید و در تنظیمات افزونه جایگزین کنید.

REST API وردپرس به‌طور پیش‌فرض درخواست‌های مرورگر از دامنه‌ی دیگر (CORS) را می‌پذیرد؛ اگر افزونه‌ی
امنیتی دارید، دسترسی عمومی به `/wp-json/wp/v2/` (posts، pages، categories، tags و users برای نام نویسنده)
را باز بگذارید.
